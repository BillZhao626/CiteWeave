# M0 实测与选型结论

日期：2026-09-11。新代码、新原创数据、新容器实验。**M0 的三项受限工程可行性实验通过；v0.1 核心契约冻结，M1 首包已开始。当前不是生产就绪 RAG，也没有模型生成问答功能。**

## 结果与证据

| 实验 | 实际运行 | 结果 | 证据文件 |
|---|---|---|---|
| P01 | 8 份不同内容的原创中文 PDF、1 份 emoji 文本、1 份结构化表格；30 个精确 span | 30/30 文本与版本一致；24 个局部 PDF 引用按字符映射高亮；8 页渲染已视觉核对，包括 90°/270° | `reports/p01-evidence.json`，`experiments/p01_evidence.py` |
| P02 | 1000 原创片段、30 问；真实 Qdrant dense/sparse 与 RRF；本机 GPU embedding/reranker | 两路 scope 过滤通过；Qdrant BM25 与手算实现最大绝对差 0.000001893；未 OOM | `reports/p02-retrieval.json`，`experiments/p02_*.py` |
| P03 | 真实停止 Valkey、SIGKILL worker、更换容器/进程身份、提交后未 ACK 再投递、16 并发相同幂等键 | 3/3 故障场景收敛；各任务有效结果仅 1 条；同键异内容、过期 lease、旧 fence 提交被拒绝 | `reports/p03-recovery.json`，`tests/test_jobs.py` |

这些成绩与私有审计目录中的旧项目测试无关。P01 的表格验证是 JSON 单元格位置与表头关系，**不等于通过 PDF 表格提取**。PDF parser 只支持简单文本与指定旋转，复杂多栏、OCR、裁剪框、混合字体布局需要单独扩展与验收。

P03 的恢复扫描由实验控制器调用；结果证明数据库/outbox/fencing 机制可行，不表示已交付持续调度、取消、死信、有限重试或外部 API 副作用补偿。未 ACK 场景包含显式重复投递，不能解释为单靠 broker 自动恢复就已认证。

## 检索消融

| 策略 | Recall@10 | MRR@10 | nDCG@10 |
|---|---:|---:|---:|
| E5-small 稠密 | 29/30，96.67% | 0.7772 | 0.8243 |
| 中文 BM25 | 25/30，83.33% | 0.6053 | 0.6616 |
| 应用层 RRF | 29/30，96.67% | 0.7689 | 0.8155 |
| RRF + BGE reranker v2-m3 | 29/30，96.67% | 0.8944 | 0.9131 |

RRF 没有提高本轮召回，MRR 略低于 dense；保留混合架构是为了可解释词法通道、技术标识符与后续领域语料对照，不宣称融合天然更好。重排改善相关结果位置，无法补救候选池丢失。

未召回问题：“怎样查看一次请求慢在哪里？”对应开发者链路耗时记录片段。其他首位错误包括引用文本不一致、批量评测断点恢复、并发保护、提示词效果对比。没有围绕这些问题改写测试答案或调参刷分；进入 M2 时增加近义表达、困难负例和独立标注集。

本轮 970 个背景片段大多与目标无关，30 问是设计时可见的 dev 集，非独立测试集。这些数字只能证明检索链路与评测脚本能运行，不能作为真实业务准确率、问答正确率或泛化能力写入简历。

## 本机模型资源

环境：i5-13500H / 16 GB / RTX 4060 Laptop 8 GB。Windows Python 3.12.8；隔离 GPU 环境 torch 2.13.0+cu126；FP16；短文本最大 256 tokens；embedding batch=8，reranker batch=4。

| 项目 | E5-small | BGE reranker v2-m3 |
|---|---:|---:|
| 本地缓存模型加载 | 2.59 s | 5.58 s |
| 模型峰值 allocated VRAM | 237.86 MiB | 1096.51 MiB |
| 模型峰值 reserved VRAM | 242 MiB | 1116 MiB |
| 测量末尾进程 RSS | 1566 MiB | 2664 MiB |
| 运行耗时 | 1000 片段编码 1.35 s；30 问批编码 0.079 s | 每问 20 候选重排 p50 0.057 s / p95 0.089 s |

模型加载时间不含下载、Python 导入与首次系统库初始化；RSS 是测量末尾读数，不是持续采样峰值；显存是 torch 进程分配，不是整机全部占用。检索脚本 p95 约 0.071 s 包含两路网络请求与本地公式对照，不是线上查询端到端延迟。没有付费生成调用，API 花费 ¥0。

重排时系统可用内存约 1.9 GB，说明 16 GB RAM 比显存更值得控制。采用两个进程分时测量，完整业务后续需要测量服务共驻和并发；不能将分时结果作为三模型同时驻留的容量结论。

## 最终冻结与保留选择

- Python 3.12 + FastAPI/Pydantic；PostgreSQL 为状态真值；Qdrant 1.16.3 + client 1.16.2；Celery 5.6.3 + Valkey 8.1.5。Python 依赖由 uv.lock 固定；容器按实际拉取 digest 固定。
- 中文稀疏选 jieba + 自有 BM25 snapshot 编码，Qdrant 稀疏 dot product，显式应用层 RRF；保持逐阶段可测量。
- 个人设备首个可运行 profile 选 multilingual-e5-small + BGE reranker v2-m3。两者使用公开权重，固定 Hugging Face revision；不假装完成了全部候选的优胜比较。BGE-M3 embedding、Qwen reranker 与真实语料对照延后。
- 元数据首包使用 psycopg 参数化 SQL 展示事务不变量；完整迁移/仓储层仍按 SQLAlchemy + Alembic 路线演进，不把“依赖已安装”当成 ORM 已落地。
- React 19 + TypeScript + Vite + Tailwind 4，shadcn/ui 组件；当前工作台展示原创证据定位、消融、恢复结果，后续再接入知识库业务流程、PDF.js 和 TanStack Query。

冻结详情见 [M0 冻结范围](specs/00_M0冻结范围.md)。未完成的完整 S-01/S-02/S-03 保留为目标设计。

## 独立实现评审发现与处理

1. **局部引用不能沿用整块 bbox。** 增加逐字符 map 切片，并拒绝没有 map 的局部 PDF span；回归测试覆盖。
2. **模型测试需要真实 GPU 环境。** 原可用 torch 为 CPU 构建，本项目创建 D 盘独立 CUDA venv，模型和缓存也在新目录；没有复用旧项目模型配置。
3. **客户端/服务端版本需要配套。** 初测 client 1.19 与 server 1.16 跨 minor；锁为 client 1.16.2 后重跑真实稀疏、dense 与过滤，结果一致，不通过关闭版本检查隐藏问题。
4. **任务完成必须与结果提交原子化。** 状态更新、结果唯一约束、fence/lease 校验在同一个 PostgreSQL 事务中；worker identity 改变后仍能恢复。
5. **表格不得只有裸数值。** table_cell 明确行列坐标与表头关系；解析能力不足就限制认证范围。
6. **认证主体不得来自请求体。** M1 workspace 来自服务端个人 token 配置；伪造 workspace 字段被 422 拒绝；列表跨 workspace 不可见。

剩余风险按后续包验收：API 请求总大小/速率与超时、连接池、完整错误日志、cursor 分页、数据迁移、持续 outbox 调度、任务失败终态、模型超时/熔断、真实生成与语义引用评估、完整上传链路。当前只适合 loopback 开发环境。

## 环境事件记录

经用户明确授权，临时停止旧 RAGFlow 的 5 个容器，保留容器和数据卷。新服务均为 `citeweave-m0-*`，端口只绑定 127.0.0.1。未运行全局 prune、factory reset 或旧项目清理命令。

Docker Desktop 重启碰到 Windows 残留 AF_UNIX 套接字，日志依次指向 Docker/run 与 docker-secrets-engine。只将这两个运行目录改名备份并重建空目录后恢复；备份仍位于原 AppData 目录旁，没有更改磁盘镜像、项目容器或数据卷。类似问题见 [Docker 官方仓库问题记录](https://github.com/docker/desktop-feedback/issues/531)。

模型调用方式依据 [E5 模型卡](https://huggingface.co/intfloat/multilingual-e5-small)、[BGE 重排模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)；权重许可证分别标记 MIT / Apache-2.0。第三方组件权利与个人原创代码权属分开记录。
