# 本地运行与复现实验

> 此文保留 M0 实验复现。M1 产品使用 [M1 本地开发入口](M1_LOCAL_DEVELOPMENT.md)，工作台地址为 18080，真实生成需要个人 DeepSeek API。不要把下面的 M0 启动方式当作 M1 完整服务。

所有命令在新项目根目录用 PowerShell 执行。只操作 `citeweave-m0` Compose，不要在旧 RAGFlow 目录运行这些命令。没有模型 API key 要求，没有付费调用。

## 已安装环境的启动

```powershell
.\.venv\Scripts\python.exe experiments/bootstrap.py
docker compose --env-file .env -f deploy/compose.m0.yml up -d postgres broker qdrant
.\.venv\Scripts\python.exe experiments/serve.py
```

在另一个终端运行：

```powershell
Set-Location apps/web
pnpm dev
```

工作台 `http://127.0.0.1:15173`；API 文档 `http://127.0.0.1:18080/docs`。工作台只读原创实验数据，不要求管理员 token。知识库 API 的 Authorize 使用本项目 `.env` 中的 `CW_ADMIN_TOKEN`，不要提交、截图或公开这个值。创建需要 Idempotency-Key；相同键和内容返回原对象，不同内容 409。

## 干净 Python 环境

先安装 Python 3.12 和 uv。使用现有 uv 可直接：

```powershell
$env:UV_CACHE_DIR = Join-Path $PWD '.cache/uv'
$env:UV_LINK_MODE = 'copy'
uv sync --frozen --group dev
uv run python experiments/bootstrap.py
```

前端 Node 22.20+，pnpm 11.19；`pnpm install --frozen-lockfile`，然后 `pnpm build`。全新 clone 需要先生成 P01 fixture、完成或恢复实验报告，工作台才有可展示数据。

## P01：证据定位

依赖 Poppler 的 `pdftoppm` 在 PATH，可使用个人安装或 Codex runtime 提供版本。

```powershell
.\.venv\Scripts\python.exe experiments/p01_evidence.py
```

生成在 `.artifacts/p01`，包括原始文件、规范块、字符坐标、渲染图和 `contact-sheet.png`。脚本自动报告 30 个精确引用；视觉核对是独立步骤，重跑会把 JSON 状态恢复为 `automated_pass_visual_review_pending`。逐页核对局部高亮后再记录 review，不能仅凭生成成功标记视觉 PASS。

## P02：模型与检索

GPU 环境 `.runtime/ml` 与业务 `.venv` 分离。创建方式：

```powershell
python -m venv .runtime/ml
.\.venv\Scripts\uv.exe pip install --python .runtime/ml/Scripts/python.exe torch==2.13.0 --index-url https://download.pytorch.org/whl/cu126
# 其余包按 requirements-models.lock 安装；torch 已由上一步固定到 CUDA 构建。
Get-Content requirements-models.lock | Where-Object { $_ -notmatch '^torch==' } | Set-Content .runtime/model-rest.lock
.\.venv\Scripts\uv.exe pip install --python .runtime/ml/Scripts/python.exe -r .runtime/model-rest.lock
.\.runtime\ml\Scripts\python.exe experiments/model_download.py
```

模型下载首轮约 2.8 GB 权重，另有 torch/依赖与缓存空间；脚本固定本轮公开仓库 revision 并保存 `.runtime/models.json`。更新模型须显式修改 revision 并重跑评测，不得把未来 main 版本与本轮指标混为一谈。离线测量脚本只读已下载目录。

```powershell
.\.venv\Scripts\python.exe experiments/corpus.py
.\.runtime\ml\Scripts\python.exe experiments/p02_models.py embed
.\.venv\Scripts\python.exe experiments/p02_retrieval.py
.\.runtime\ml\Scripts\python.exe experiments/p02_models.py rerank
.\.venv\Scripts\python.exe experiments/p02_retrieval.py report
```

原始排序、候选池、向量和模型测量位于 `.artifacts/p02`；可分享摘要位于 `docs/reports`。已有实验集合只用于 M0；真实业务不得继续往它写入。

## P03：任务故障注入

```powershell
docker compose --env-file .env -f deploy/compose.m0.yml --profile jobs up -d --build worker
.\.venv\Scripts\python.exe experiments/p03_recovery.py
```

此脚本确实停止本项目 broker、SIGKILL 并重建本项目 worker；运行时避免同时提交本项目其他开发任务。不会删除 volume。每轮生成新 UUID，数据库保留本轮任务、outbox、events、effects，便于复盘。恢复时间字段为最后轮询阶段耗时，不包含容器重建和显式等待；不要误作端到端恢复 SLA。

M0 worker payload 中 pause_before/pause_after 是故障注入专用字段，未暴露给正式 API。当前任务执行逻辑只是确定性写入结果；业务摄取/eval 尚待接入。

## 回归与契约

```powershell
.\.venv\Scripts\python.exe experiments/check.py
.\.venv\Scripts\ruff.exe check src tests experiments
.\.venv\Scripts\python.exe experiments/export_contracts.py
```

`experiments/check.py` 自动读取本项目环境，包含真实 PostgreSQL 集成测试；直接 `pytest` 未提供数据库配置时会跳过集成测试，不能冒充全量通过。`docs/reports/tests.xml` 是实际 JUnit 结果。

停止新项目实验容器：`docker compose --env-file .env -f deploy/compose.m0.yml --profile jobs stop`，不加 `down -v`。恢复原先暂停的 5 个旧容器应单独执行 `docker start` 指定原名，并先考虑 16 GB 内存能否承载两套服务。
