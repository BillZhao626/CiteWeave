# M3 bounded context and Dense experiment isolation

Status: experimental, selection pending. No active ingestion profile or immutable source identity changes.

Parent retrieval is a deterministic, query-independent paragraph projection over stored original children. Native Blocks are lines on the measured corpus. Geometry gaps, indentation, visible numbered/list boundaries and hard 800-character / 12-member limits define parent membership. Six reranked children resolve parents; round-robin member projection respects the original global 30-span / 3200-character generation cap. ParentContext metadata is distinct from cited EvidenceSpan. The answer receives only original labeled member spans, never a synthetic parent citation. This is a heuristic paragraph abstraction, not a semantic section parser; headings without reliable visual cues and tables can be ambiguous. C2 remains named bounded neighbor expansion.

Dense model identity includes model/revision/dimension/normalization/prefix/token bound. Gateway requests and responses must match this identity. The local maintenance switch loads one Dense model plus the unchanged BGE reranker, preventing an accidental E5/BGE dimensional mixture. During BGE mode E5 requests fail explicitly before indexing or generation; restore E5 after the experiment. This does not add transparent online multi-model serving.

Separate experimental Qdrant collections preserve the immutable child IDs and unchanged BM25 vector calculation, checked against the original fingerprint. PostgreSQL OperationRow stores embedding provenance and an expiring fenced attempt; IndexRow stores ownership and BUILDING/EXPERIMENT_READY. Every reclaimed attempt writes a new collection; stale attempts cannot publish. Completed bindings are captured in normal QueryRun/EvalRun snapshots under the governance lock. Existing lifecycle protection covers captured references; live experiment attempts are additionally protected from GC. Version.index_collection never changes. No schema migration is required because both durable metadata structures already exist; no external JSON file serves as business authority.

Alternatives rejected for this experiment: overwrite E5 collections; select a collection by naming convention alone; put 1024-dimensional BGE queries into 384-dimensional E5 indexes; add BGE sparse/multi-vector at the same time; call a new bespoke answer/evaluation pipeline. A future general online embedding migration service would need product lifecycle/API design and is outside this bounded experiment.
