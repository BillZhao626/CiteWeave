# M2 能力边界

1. **单人本机 production-oriented alpha。** token/cookie、workspace 作用域，不含多人 RBAC、SSO、公网 HTTPS、SaaS 运营或云部署验收。
2. **效果基线偏弱。** 三份公开历史标准上的 48 题冻结集揭示了 line-based chunk、RRF 截断、最终证据覆盖不足和不当拒答。M1 基线 Judge correctness 平均 0.3021，M2 单轮 0.3229（均 n=48），最终 gold 覆盖均为 0.2305。工程可靠性通过不能替代回答质量；不可作为一般业务准确率宣传。M2 不按冻结 test 调参。
3. **PDF 范围有限。** 仅可提取文字的简单文档；不做 OCR、多栏顺序恢复或复杂表格解析。裁剪 / 非零 MediaBox 原点拒绝，物理页与印刷页码可能不同。
4. **规模与资源。** 每 KB ≤10 文档，每 PDF ≤10 MiB / 100 页 / 1000 chunks；问题与片段 ≤160 codepoints；模型 token 溢出明确拒绝。单 Query、worker=1、GPU=1。短时负载无 OOM 不代表长时间稳定性；没有 CPU-only 和第二台全新机器的安装验收。Windows RSS 只是 working set，不代表模型总提交内存。
5. **检索仍是 M1 策略。** BM25 是每版本局部统计；融合不混加局部分数。chunking 无跨行事实补全；M2 提供丢失层级诊断，未通过测试集调整模型或参数。
6. **证据定位与语义分开。** 版本、页、quote/span/box 能独立复核；这不等于每个 claim 被证据充分支持。没有自动 claim-level entailment 认证。LLM Judge 可错，3 个项目所有者复核样本不构成 Judge 准确率验证。
7. **维护保守。** GC 仅手动清理已确认归属且无引用的派生索引；保留原件、Blob 和历史 Run，存储会增长。未知归属 / 老数据缺少物理快照时更保守。rollback 为单文档，不是整个 KB 的原子 release。
8. **恢复边界。** 已做 PG + Blob 到隔离环境的真实恢复，不包括磁盘彻底损坏、长期断电、跨机迁移、异地备份、在线 PITR 或自动恢复切流。不声称 exactly-once。
9. **取消与未知结果。** HTTP 取消尽快关闭上游；网络与供应商结算可能有延迟。GPU 已开始的一个有界 batch 无法瞬间中止。worker 中断后的未知 Query / Judge 不自动重发，保留失败和预算预留。
10. **预算不是供应商硬限额。** ¥50 只约束本应用已知估算 + 未知预留，同一 key 在项目外消费不可见。费率卡固定日期，实际账单 unavailable；更新模型或价格必须同步费率和测试。未知费用不能写成 0。M1 导入 Judge 无实际预约时间的历史行按原创建时间归属，其精度不等于新记录。
11. **尚未公开发布。** 没有远程仓库、个人署名提交、最终开源许可证或完整 SBOM。业务代码独立实现，第三方框架 / 模型 / 组件及公开资料保留各自权利，不作“所有依赖皆个人版权”保证。原始公开 PDF 和本地运行数据不纳入候选。
12. M2 不含 MCP 产品接入、Agent runtime、OCR、Kubernetes、Temporal 或对象存储迁移。完成 M2 后停止，后续工作另行确定。

测试输出保留两条 Starlette/httpx、AnyIO 上游弃用警告；未静默屏蔽。
