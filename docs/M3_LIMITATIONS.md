# M3 limitations

- Single owner, local machine alpha. No public HTTPS, multi-user RBAC, untrusted-tenant isolation, long-running SLA, Kubernetes, OCR, MCP product integration or Agent runtime. API-first endpoints can be integrated later; an implemented MCP product is not claimed.
- Parser supports verified text PDFs and supported rotations. Scans, complex multi-column layouts, ligature mappings, arbitrary tables and layout ambiguity can fail or produce poor retrieval. Neighbor geometry is a bounded heuristic; it does not recover sections across pages or prove semantic continuity.
- The benchmark is 3 small historical English standards PDFs with Chinese questions. Final finite-gold coverage is about .54 Dev/.51 Test. No-recall was not the dominant observed Dev failure, but multi-part/cross-document answers and partial refusals remain imperfect. Gold is finite, not exhaustive semantic truth.
- Judge v4 uses deterministic exact-refusal policy plus a fallible LLM. Human reference is owner-submitted AI-assisted review. Calibration 24/24 is not independent LLM accuracy. Three formal Test pairs are unavailable due to Judge validation failures; all remain visible.
- Physical citation identity and semantic support are distinct. Formal Test physical citations passed 59/59, while three assessed factual sentence units were unsupported. The application does not run a hard semantic-entailment validator before each final answer.
- C2 increases final context and API tokens. Test query p95 increased from about 1.83 to 3.54 seconds; one model connection retry took about 5.21 seconds total. Timings are historical local observations, not controlled QPS or sustained capacity. CPU-only performance and a second physical machine are unverified.
- Provider costs are estimates from recorded usage and a versioned rate card. The actual vendor bill and activity outside this local database are unavailable. Unknown interrupted calls retain budget reservation. Rate cards need deliberate future maintenance; no claim of always-current pricing.
- At-least-once task execution with fenced effective publication, not exactly-once. Backup restore is local and requires intact PG dump + CAS, matching application/schema and installed models. No automatic offsite encryption, PITR or hardware-loss RTO guarantee.
- MIT covers original material only. Dependencies/models/standard excerpts retain their terms. SBOM is an installed-component inventory, not full OS/CUDA provenance, a vulnerability audit or legal ownership clearance. Initial project planning included prior-code review; no formal clean-room claim.
- Test is frozen and has now been used for this final comparison. Further quality tuning requires separate authorization and a new evaluation discipline; M3 completion does not start M4.
