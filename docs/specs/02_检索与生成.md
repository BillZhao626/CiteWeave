# S-02 检索、证据选择与生成

> M0 已执行：已验证不变量以 [M0 冻结范围](00_M0冻结范围.md) 为准，本文其余部分仍是完整目标设计。实测结果见 [M0 报告](../05_M0实测与选型结论.md)。

状态：待 M0 冻结。任何默认参数变化都建立新 policy revision，不在看过评测结果后悄悄改协议。

## 摄取到可查询

ingestion_job：queued → validating → parsing → normalizing → chunking → embedding → indexing → verifying → succeeded。failed/cancelled 为终态，retry_wait 仅在有限可重试错误中使用。任务完整状态由 job 表维护，每个阶段输出用不可变 hash 标识。

解析输出统一 Block：来源版本、块类型、页/位置、章节、文本、表格关系、解析器/版本。先支持 TXT/Markdown/HTML/数字 PDF；扫描件走显式 OCR 可选 profile。首版不宣称支持所有文档格式。

分块初值 400–700 embedding tokens，overlap 60–100；优先段落/标题边界，保存父块与原文区间。表格保持表头与单元格关系，长表分段携带表头。页眉/重复导航去噪保留转换证据；不得只存删改后的文本却保留原 offset。

document hash + parser/chunker/model revisions + index scope 决定派生产物身份。新的处理参数创建新 snapshot，不能就地覆盖正在服务的索引。单文件失败导致 snapshot 未 ready，不能以部分片段冒充完整成功；允许显式 partial dataset 策略，但必须在 release 上标注。

## 在线链路

1. 认证、输入限制、取得 release_map；确认所有 KB/snapshot/原件可见。
2. Query normalization 仅作公开、可配置的轻量处理；技术编号/大小写/版本符号保留原始形式。首版不默认用 LLM 改写。
3. dense 与 BM25 sparse 独立召回，均使用相同权限/KB/document revision 条件；记录原始分数和排名。
4. 在单路中先去重，然后应用层 RRF；候选稳定 ID 包含 KB 与文档版本，避免跨库短 ID 碰撞。
5. 可选 reranker 在有界窗口评分，保留原 RRF rank，超时/不可用明确降级。
6. 证据选择：去重、source/document diversity、token budget、显式方面覆盖；上下文父级扩展不能越版本/越权限。
7. 把最终证据与来源元信息序列化，生成结构化 claims；验证引用身份、原文区间和约束。
8. 严格渲染：证据不足/冲突时保留不确定性；保存 run 与真实成本。

## RRF 合同

rank 从 1 开始；score(d) = Σ 1/(60 + rank_i(d))，缺失单路不贡献；相同片段在同一路只能投一票。按 score 降序，平分按稳定 evidence key 字典序；窗口和常数进版本。

输入分值不做直接相加，不把 RRF 分数当相关概率。dense/sparse score 分布不同，除非做过带分母和版本的校准，不设统一“0.7 即可信”门槛。RRF 只融合排序，不能把库 A 的证据授权给库 B。

跨库初版分别搜索每个固定 snapshot，将每个 (KB, channel) 作为独立 ranked list，等权应用相同 RRF 公式；每 KB 每通道最多 50，合并后按全局 candidate key 去重，保留每库 budget 和来源。此策略命名为 federated_rrf_v1，分数不能直接与单库相关性阈值比较。不得把不同 KB 的原始 BM25 分数直接排序合并；未来引入跨库校准时创建新的 policy 并重新评测。

Qdrant 原生 RRF 当前采用不同默认常数与 rank 约定；未来迁移需为精确版本做等价测试，而不是照抄参数名。[官方定义](https://qdrant.tech/documentation/search/hybrid-queries/)。

## BM25 的必须验证项

- 查询与文档共用 analyzer revision；中文、英文、标点、协议编号、数字单位都有 fixtures。
- 冻结实际公式和 IDF 统计范围；跨 KB payload filter 不自动改变集合级词频统计。
- 更新/删除后 snapshot 不混用旧 IDF 与新向量；BM25 sparse 与 dense 共享 chunk identity。
- 对照公开 BM25 定义构造独立小语料，手算顺序与库输出对应；验证重复词、空查询、停用词、OOV。
- 第一版可用 Qdrant/FastEmbed 适配；native server inference 能力、实际版本及 tokenizer 必须入 lock/manifest。

学习型 sparse/多语言向量是候选替代，不在未经测量时自动取代明确 BM25 基线。

## Reranker 的选择门槛

三臂：RRF-only、RRF+BGE v2-m3、RRF+Qwen3 Reranker 0.6B。使用同一 frozen candidate pool、模型 revision、输入截断策略与 query set。先跑检索指标，只有胜出候选再进入付费生成对照，控制 ¥50 月预算。

建议提升门槛在 dev 上预注册：nDCG@10 有实质改善、evidence recall 不下降、关键拒答/越权为零、P95 延迟和显存预算可接受。阈值未校准前不选择“只取最大 rerank score 的那项”作为可信规则。模型超时退回同库同 snapshot 的 RRF 候选，保留警告，不做异库回退。

## 生成与证据验证

Prompt 结构由原创模板定义：任务边界 → 输出 schema → 当前问题与 history → 带可信来源字段的证据容器。检索正文全部是不可信数据，即使含“忽略指令/调用 URL”等文本也不能改变系统策略；核心生成路径不开启文件/网络工具。

生成输出包含 claim 文本、evidence 临时 ID、需要的支持区间/quote 和不足说明。服务端执行三类验证：

| 层 | 作用 | 不能证明什么 |
|---|---|---|
| identity/locator | 当前 run 的证据 ID、版本、权限、区间存在 | 不能证明答案正确 |
| quote_exact | 规范文本中精确匹配、hash 与坐标一致 | 相同单词不等于蕴含，包含否定的句子不能反向解释 |
| support assessment | 主张与证据的支持/冲突/不足，规则+可选 NLI/LLM judge+人评 | Judge 也会错；不得标成确定性真理证明 |

v0.1 对强“已验证”标识只承诺 locator/quote；语义支持显示 assessment 方法。表格数字要连同单位、表头、对象、时间；文档发布机构和正文提到的对象分开。提案/草案不得自动升级为生效规范。冲突证据可以回答“来源存在冲突”，不拼出看似统一结论。

结构化输出错误最多修复一次，使用同一证据集；引用仍不合法则移除相关主张或返回不足，不能通过猜测 quote 补全。修复次数、tokens 和费用进入同一 deadline/budget；不因少量格式失败开启无界 Agent 循环。

## 可观测与回放

记录各阶段输入/输出身份、排名、候选选择原因、预算和耗时。支持 retrieval replay（固定输入候选重放）与 generation replay（固定上下文再次调用）两种不同操作。确定性阶段应可重复；模型上游别名/采样变化允许新结果，但必须创建新 run，不能覆盖历史。

## 关键测试编号

R01：dense/sparse/scoped metadata 全部应用同一授权条件。R02：独立手算 RRF 去重/平分/窗口。R03：同库不同 snapshot 不混合，删除/ACL 变化优先。R04：中文/英文/技术编号/表格 qrels 分开报告。R05：候选命中但 Final-K 丢失能够归因。G01：伪造 citation/不存在 quote 拒绝。G02：否定、对象替换、版本与单位错误可检出或进入人工待审。G03：不足与冲突不被一般答案覆盖。G04：断线/超时/repair 不突破调用预算。
